Armor

Every wearable defensive item in Meridian 59 is a DefenseModifier, and each one can do three completely separate things: change how often you get hit (viDefense_base), subtract a random flat amount from every blow (viDamage_base), and multiply the damage of specific attack types up or down (GetResistanceModifiers). These three effects do not trade off against each other in any tidy way — the heaviest armor in the game gives you negative defense, and one robe actively makes you take more damage.

How a hit against you is resolved

Two separate calculations matter. First, whether the attack lands at all:

iDefense = (parry*2) + (block) + (dodge*3) + (agility*4) + (base_max_health*3/2) for each worn defense modifier: iDefense = ModifyDefensePower(iDefense) % armor adds piDefense_bonus here iDefense = iDefense + faction_defense_bonus iDefense = iDefense + (iDefense * piFlags3 / 100) iDefense = bound(iDefense, 1, 1000) chance_to_hit = bound(attacker_offense * 55 / iDefense, 10, 95) % percent

kod/object/active/holder/nomoveon/battler/player.kod:4320-4333 and kod/object/active/holder/nomoveon/battler.kod:19,330-334

Then, if it lands, how much it hurts:

for each worn defense modifier i: damage = i.ModifyDefenseDamage(damage, atype, aspell) % flat reduction i.DefendingHit() % item takes wear iResistance = ResistanceCheck(atype, aspell) damage = GetDamageFromResistance(damage, iResistance) % percentage damage = damage + attack-modifier bonus if damage <= 0: damage = 1 damage = bound(damage, $, (base_max_health + 2) / 3) % 1/3 max HP, rounded up damage = bound(damage, $, 30) % MAX_DAMAGE_PER_HIT

kod/object/active/holder/nomoveon/battler/player.kod:4568-4617 (caps at :109,:113)

Order matters: the flat reduction from armor is subtracted before the resistance percentage is applied, and every worn defense modifier gets its own independent subtraction. Attack-modifier bonuses (gauntlets, rings) are added after resistance, so armor never scales them down.

Effect 1 — defense power

On Use, an item copies viDefense_base into the instance property piDefense_bonus, and the default handler simply adds it to your defense score.

DefaultValues(): piDefense_bonus = viDefense_base piDamage_reduce = viDamage_base ModifyDefensePower(...): return defense_power + piDefense_bonus

kod/object/item/passitem/defmod.kod:31-32, 41-47, 95-98

The defense score is a raw number clamped to 1–1000. It is dominated by agility (×4), dodge (×3) and base max health (×1.5), so for the worked example below it comes to 665 — which puts a ±50 item swing at roughly 7–8% of the whole score. Shields are the exception: Shield.ModifyDefensePower deliberately returns the defense power unchanged and spends the bonus on Block instead (see below).

kod/object/item/passitem/defmod/shield.kod:67-70

Effect 2 — flat damage reduction

iDamageReduce = random(piDamage_reduce/3, piDamage_reduce) % integer division iDamageReduce = bound(iDamageReduce, 0, damage-1) % at least 1 damage always lands if aspell <> 0: % the attack has a magical component if atype <> 0: iDamageReduce = iDamageReduce * 2 / 3 % mixed weapon+spell else: iDamageReduce = 0 % pure spell: no reduction return damage - iDamageReduce

kod/object/item/passitem/defmod.kod:100-129

Armor plating does nothing at all against pure spell damage. A fireball, a Qor blast, or any attack with atype = 0 and a spell type set bypasses piDamage_reduce entirely — only typed resistance helps. Against a weapon that also carries a spell type (a fire-enchanted sword), you keep two thirds of the reduction.

Note the /3: the roll is random(r/3, r) with truncating integer division, so a value of 1 or 2 rolls from 0, a value of 4 or 5 rolls from 1, and 6 rolls from 2.

Effect 3 — typed resistance

Each item returns a list of [type, percent] pairs from GetResistanceModifiers. When the item is used, every pair is pushed onto the wearer's plResistances list; when it is removed, they are subtracted again.

kod/object/item/passitem/defmod.kod:65-93

Weapon types are stored positive, spell types negative (-ATCK_SPELL_FIRE). At the moment of the hit:

ResistanceCheck(atype, aspell): iMaxRes = 0 ; iMinRes = 0 for each [value, type] in plResistances that MATCHES the attack: iMaxRes = max(iMaxRes, value) iMinRes = min(iMinRes, value) iMaxRes = bound(iMaxRes, $, 100) % MAX_RESISTANCE iMinRes = bound(iMinRes, -100, $) % MIN_RESISTANCE return iMaxRes + iMinRes GetDamageFromResistance(damage, value): if value > 0: return damage * (100 - value) / 100 else: return damage * (-100 + value) / -100

kod/object/active/holder/nomoveon/battler.kod:189-265; constants at kod/include/blakston.khd:1521-1523

A match is (atype & type) <> 0, or the wildcard: ATCK_WEAP_ALL matches any weapon attack and ATCK_SPELL_ALL matches any spell attack.

kod/object/active/holder/nomoveon/battler.kod:200-242

Resistances of different types do not stack — only the single best positive and the single worst negative are used. Leather armor's +5 against ATCK_WEAP_ALL and chain's +20 against ATCK_WEAP_SLASH would give you 20, not 25. Resistances of the same type do stack, because AddResistance adds into the existing list entry.

kod/object/active/holder/nomoveon/battler.kod:268-289

Two consequences worth internalising:

  • Chain armor (bludgeon +15) plus a simple helm (bludgeon +10) gives +25 vs bludgeon — same type, so they add.
  • A helm (+15 vs all spells) worn with a knight's shield (−20 vs all spells) gives −5 — same type, so they add, and you end up taking more spell damage than bare-headed.

kod/object/item/passitem/defmod/armor/chain.kod:57-64; helmet/simphelm.kod:67-71; helmet/helm.kod:72-76; shield/knhtshld.kod:56-61

A full kit

Chain armor + simple helm + metal shield (block check succeeded), 20-point slash. Three independent flat rolls of random(0,2), random(0,1), random(0,1), then slash resistance 20 (chain) + 10 (metal shield) = 30 because they are the same type.

damage 20 -> 16..20 after three reductions -> * 70/100 -> 11..14, mean 12.08 same kit vs bludgeon: resistance 15 (chain) + 10 (helm) = 25 -> 12..15, mean 13.08

Why the good armor has negative defense

Plate, nerudite, scale and chain all carry a negative viDefense_base. That number is subtracted straight out of your defense score, which raises your attacker's chance to hit.

Layering

Robes occupy ITEM_USE_BODY | ITEM_USE_LEGS but explicitly permit pants and shirts to coexist with them, so a caster can stack robe (+20) + pants (+5) + shirt (+5) = +30 defense and +10 spellpower with zero weight penalty and no armor. Armor and a robe cannot be worn together — both claim the body slot.

Shields

Shields work differently from every other defensive item, and the difference is easy to miss:

  • Shield.ModifyDefensePower returns the defense power unchanged. A shield's viDefense_base is never added to your defense score.
  • Instead it is added to your Block ability, which feeds the iBlock term of the defense formula (weighted ×1, the weakest of the three defense skills):
    GetBlockAbility(who) = bound(GetSkillAbility(SKID_BLOCK) + piDefense_bonus, 1, 120)
  • The flat damage reduction only applies if you have the Block skill and pass a Block skill check, with piDefense_bonus as the modifier:
    num = ((100 - agility) * block_ability / 100) + agility + piDefense_bonus success if random(1,100) <= num

kod/object/item/passitem/defmod/shield.kod:61-89 · kod/object/passive/skill.kod:223-241,288-292 · kod/object/passive/skill/block.kod (requisite stat defaults to agility)

Worked example: agility 40, block ability 60, orc shield (+20). num = (60*60/100) + 40 + 20 = 36 + 40 + 20 = 96 — the shield's reduction fires 96% of the time. With a metal shield (+5) it is 81%.

Any Shield-class item in hand switches your Block skill on: Player.GetBlockAbility returns 0 outright if LookupPlayerShield finds nothing. A torch counts as a Shield, so holding a torch actually contributes your block ability to your defense score (with a +0 bonus).

Faction shields are special

The SoldierShield family bypasses the Block requirement entirely — it copies the base DefenseModifier reduction code so the flat 2 damage applies whether or not you can block, and it overrides DefendingHit to take no wear at all. It also carries the faction-enemy damage rule: a player attacked by a faction enemy who is wearing one takes an extra 15%, applied after the damage caps.

kod/object/item/passitem/defmod/shield/soldshld.kod:563-579,592-620 · kod/object/active/holder/nomoveon/battler/player.kod:4620-4631

The rebel shield scales its reduction with faction rank (rank is bounded 1–10):

piDamage_reduce = viDamage_base + ((piFactionRank / 3) - 1) = 2 + (rank/3) - 1 rank 1-2 -> 1 rank 3-5 -> 2 rank 6-8 -> 3 rank 9-10 -> 4

kod/object/item/passitem/defmod/shield/soldshld/reblshld.kod:153-159 · soldshld.kod:101,192-193

The source comment on that line says "This ranges from 2-4", but the arithmetic yields 1 at ranks 1–2. The code is what runs.

Totems

The six totems (Totem and TotemOne–TotemFive) descend from DefenseModifier but define no viDefense_base or viDamage_base, so they inherit 0 for both and have no defensive effect whatsoever. They are quest items that occupy a hand slot (weight 100, bulk 100) and drop when unused.

The spellpower penalty

Every item you are using contributes its viSpell_modifier to the spellpower of anything you cast. This is a spellpower modifier, not a mana-cost modifier — the mana cost of a spell does not change.

Condition, wear and breaking

Every item rolls its starting hit points once, at creation:

piHits_init = random(viHits_init_min, viHits_init_max) piHits = piHits_init

kod/object/item.kod:118-119

Each time you take a hit, every worn defense modifier is sent DefendingHit — whether or not it actually did anything. The default chain is two nested rolls:

DefenseModifier.DefendingHit(): if random(1,100) < 50 -> propagate % 49% Item.DefendingHit(): if random(1,100) < 75 -> piHits - 1 % 74% if piHits <= 0 -> ItemBrokenInBattle() net chance to lose 1 hit point per incoming blow = 0.49 * 0.74 = 36.26%

kod/object/item/passitem/defmod.kod:18,133-142 · kod/object/item.kod:18,836-871 · kod/object/active/holder/nomoveon/battler/player.kod:4574

So a fresh chain hauberk (550–650 hits) survives roughly 1500–1800 incoming blows before it falls apart.

Mend

The Kraanan spell mend (level 4, 9 mana, one sapphire and one orc tooth) is the only repair.

iMultiplier = bound(75 + iSpellPower/5, 75, 95) % 100 for immortals iAmount = GetMaxHits() * iMultiplier / 100 SetMaxHits(iAmount); SetHits(iAmount)

kod/object/passive/spell/mend.kod:40-42,53-57,112-139

Mend does not restore an item — it permanently lowers the ceiling. Every cast multiplies the item's maximum hits by 75–95%, and the loss compounds with each cast. A plate hauberk mended five times at spellpower 99 (95% each) is down to 77% of its original maximum. Once piHits_init drops below viHits_init_min the description permanently reads "has been repaired before", and resale value drops quadratically.

Mend refuses two cases: an item already at full hits ("already in perfect condition") and an item at exactly 0 hits ("beyond salvage"). A broken item can never be repaired — unequip and mend before the last hit point goes.

kod/object/passive/spell/mend.kod:67-104

Shirts and pants return FALSE from both CanMend and ReqRepair; armor and shields return TRUE from ReqRepair and inherit the item-attribute-aware CanMend.

kod/object/item/passitem/defmod.kod:144-167 · defmod/armor.kod:66-69 · defmod/shield.kod:154-157 · defmod/shirt.kod:167-175 · defmod/pants.kod:127-135
